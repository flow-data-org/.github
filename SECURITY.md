# Безопасность

## Утечка ключа или токена

Если секрет попал в репозиторий, issue, PR, лог или чат:

1. **Немедленно отозвать** ключ у провайдера и **перевыпустить** новый.
2. Обновить значение в GitHub Secrets / локальном `.env`.
3. Проверить логи провайдера на использование старого ключа.
4. Только после этого, при желании, очистить историю (`git filter-repo`) — это гигиена, а не защита.

> **Удаление файла или коммита не делает ключ безопасным.** Он остаётся в истории git, форках и кэшах. Считайте любой попавший в репозиторий ключ скомпрометированным.

## Как не допустить утечки

- Секреты только в GitHub Secrets (CI) и локальном `.env` (в `.gitignore`).
- Включены Secret Scanning и Push Protection (настраивается в организации).
- В CI работает gitleaks (`.github/workflows/gitleaks.yml`).

## Сообщить об уязвимости

Не создавайте публичный issue. Используйте приватный репорт: вкладка **Security → Report a vulnerability** в нужном репозитории.
